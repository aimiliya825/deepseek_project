# DJI Action 4 Teardown — Build Contracts

Shared workspace: `E:\deepseek_project\dji-action4-3d`
Final deliverable: a single self-contained `index.html` (generated by Lead), no external assets.

## Global environment

Scripts are classic scripts (no ES modules, no server required), loaded in this order by the template:

1. `vendor/three.bundle.js` — exposes `window.THREE` (Three.js r186 + OrbitControls + postprocessing)
2. `src/parts-data.js` — exposes `window.ACTION4_PARTS`, `window.ACTION4_META`
3. `src/model.js` — exposes `window.Action4Model`
4. `src/ui.js` — exposes `window.Action4UI`
5. `src/app.js` — Lead's scene + interactions

Local file copies must not be fetched at runtime. All visuals are procedural (CanvasTexture is allowed).
Coordinate system: X = width, Y = height, Z = depth; lens faces **+Z**. Y is up.
The model is centered on the world origin. Assembled proportions: chassis ≈ 7.4 (X) × 4.6 (Y) × 3.2 (Z).

## `src/model.js` contract (owner: modeler)

```js
window.Action4Model = {
  /**
   * @param {object} THREE  the global THREE namespace from vendor/three.bundle.js
   * @returns {{
   *   root: THREE.Group,
   *   parts: Record<string, {
   *     id: string,
   *     group: THREE.Group,          // direct child of root, position starts at (0,0,0)
   *     anchor: THREE.Object3D,      // child of group; label anchor in assembled geometry
   *     pickMeshes: THREE.Object3D[],// meshes for raycasting (all have userData.partId set too)
   *     materials: THREE.Material[], // unique per part, NOT shared with another part (if avoidable)
   *     fadeMaterials?: THREE.Material[] // body shell only; must support transparent fading
   *   }>,
   *   update(dt, elapsed, state): void, // subtle model animation (screens, LEDs, etc.)
   *   dispose(): void
   * }}
   */
  create(THREE) {}
};
```

Hard requirements:

- Build every mesh procedurally. No external model/texture files, no network requests.
- Create one part group per id in `window.ACTION4_PARTS`, with exactly those ids. Do not add parts not in the list.
- Geometry is authored in place (assembled position); each **part group's transform starts at identity**. The app performs the exploded translation using each part's `explode` vector from `parts-data.js`.
- Each `anchor` is placed at a sensible point on that part (outside surface recommended) for a label leader line. It should start from assembled coordinates and move with the group.
- `pickMeshes` must include every visible mesh belonging to the part. Set `mesh.userData.partId = id`; make labels/anchors `visible = false` and never pickable.
- `materials` must not be shared between parts (clone templates per part). Emissive-capable materials should have an `emissive` color set to the part accent (`part.accent` from parts-data) with `emissiveIntensity = 0` at rest. The app animates emissiveIntensity for hover/selection.
- Body shell part must expose `fadeMaterials` so the app can fade the shell into a translucent hologram during explosion (set `transparent = true` safely in the app).
- Keep the total mesh count under ≈ 320 and triangle count under ≈ 300k. Reuse geometries/materials within a part where possible.
- Use `CanvasTexture` for screens/labels/PCB/knurling; set `colorSpace = THREE.SRGBColorSpace`, `anisotropy = 4`.
- All materials should look good with the scene's physically based lighting + generated cube environment map. Prefer MeshPhysicalMaterial/MeshStandardMaterial with realistic metalness/roughness; do not rely on direct lights for screen content (use MeshBasicMaterial for screens with `toneMapped = false`).
- No `OrbitControls`, no camera, no lights, no renderer in this file. No DOM UI. Only `window.Action4Model`.
- `update()` must be cheap and robust; screens/LED can pulse, but do not mutate geometry every frame.
- Must run in `file://` context and in a headless Edge/Chromium WebGL context; avoid unsupported browser APIs.
- Handle WebGL context loss gracefully at app level, not here.

### Visual/geometry direction (must follow)

Exterior recognizably DJI Osmo Action 4, landscape body:

- Dark graphite rugged rounded rectangular chassis with subtle bevels and rubberized side grip. Front bezel slightly inset.
- Front: large circular lens at x≈-1.75, y≈+0.15 on z≈+1.6 face. Knurled outer protective ring (replaceable), thin amber accent ring, black barrel, recessed multi-element glass with realistic reflections/transparency.
- Front right: small 1.4″ display (≈2.2 × 1.35 units) at x≈+1.95 with procedural teal camera UI, dark bezel, glass. DJI wordmark + small "ACTION 4" lettering on front face.
- Rear (-Z): 2.25″ touchscreen ≈5.2 × 3.0 units with dark bezel, procedural camera preview UI, status bar, battery/histogram/REC overlay; glass reflections.
- Top: red-ringed shutter button, smaller QS button, speaker/mic perforations, small status LED. (Top face y≈+2.3.)
- Sides: battery door seam + sliding latch on +X, port cover on -X with USB-C recess, subtle grip ribs.
- Bottom (y≈-2.3): magnetic quick-release mount plate with two magnet insets, mechanical lock, 1/4″ thread suggestion.
- Internals (visible only via transparent shell in exploded state, so model them fully):
  - 1/1.3″ sensor module: PCB carrier, gold contacts/frame, dark die, copper cold plate.
  - Mainboard: dark solder-mask PCB with procedural traces, multiple chips, shields, USB-C connector, microSD slot.
  - Battery: removable slab ≈2.4 × 3.8 × 1.2 with label ("DJI EXTREME", 1770mAh), amber accent stripe. Include a thin battery-door presentation on +X.
  - Thermal module: copper heat spreader + dense aluminum fin stack, heat pipe.
  - Front/rear display glass + bezels are their own part groups (not part of body fadeMaterials).
  - Top controls group: shutter/QS button caps + mic grille insert.
- Mount group should be detachable downward and include its own top magnetic plate.
- Every part gets a small emissive detail (LED, accent line, label) so hover glow is legible.

All visual details allowed to be stylized for readability, but proportions/branding/camera identity must read instantly as DJI Osmo Action 4.

## `src/ui.css` + `src/ui.js` contract (owner: ui-designer)

`src/ui.js` exposes:

```js
window.Action4UI = {
  /**
   * @param {{
   *   parts: Array, // window.ACTION4_PARTS
   *   meta: object, // window.ACTION4_META
   *   callbacks: {
   *     onTogglePart(id),
   *     onExplodeAll(),
   *     onAssembleAll(),
   *     onResetView(),
   *     onToggleAutoRotate(boolean),
   *     onFocusPart(id),       // optional camera focus
   *     onHoverPart(id|null),  // 3D hover sync
   *     onFullscreen()
   *   }
   * }} options
   * @returns {{
   *   setSelected(id|null, {detached}={}): void,
   *   setHovered(id|null): void,
   *   setPartDetached(id, boolean): void,
   *   setAllDetached(boolean): void,
   *   setAutoRotate(boolean): void,
   *   setBusy(boolean): void,
   *   setProgress(done, total): void,
   *   setConnectionState(label): void, // optional small status text
   *   toast(message): void,
   *   ready(): void
   * }}
   */
  create(options) {}
};
```

`ui.js` may create its DOM inside `#ui-root` (provided by Lead). `ui.css` owns all UI overlay styling and may target `.a4-*` classes. Do NOT style `#scene`, `#label-layer`, canvas, or the label tags (Lead owns `src/app.css`). No external fonts/assets; system font stack only. Keep the 3D viewport visually exposed: left panel ≤ 300px (≥1500px screens) and right panel ≤ 340px; both are collapsible on mobile.

UI features and visual direction:

- Top-left: DJI-style brand lockup, "OSMO ACTION 4", "TEARDOWN LAB / 01", tiny live status dot. Top-right: auto-rotate toggle, camera reset, fullscreen, primary "全部拆解"/"全部组装" action.
- Left "部件清单 / COMPONENTS" panel: indexed rows for all 11 parts with Chinese name, English tiny caps, accent dot, detached status LED; active/hover states; scrollable. Click row → select + 3D highlight; maybe camera focus.

When a part is selected: index, category, large Chinese name, English name, description, parameter rows, accent status ("已拆解"/"组装中"), and action button "拆解此部件"/"组装此部件". Keep it compact enough at 1366×768.
- Bottom-center operation guide/chips: drag rotate · wheel zoom · click part to explode · space full explode · R reset. Include a dismissible first-run hint card with stylized mouse graphic (CSS only). It should not block the model after dismissal and must auto-dismiss on first pointer interaction via callback? The app can call `ui.dismissGuide()` if you expose it; otherwise auto timeout.
- Bottom-left tiny telemetry: FPS slot? app will not update it. Show "PBR / PROCEDURAL / THREE.JS" and part progress.
- Responsive: at <1180px hide/compact left panel and make right panel a slide-over sheet; at <820px provide a bottom tray with parts and selected detail; top actions become icon buttons. No horizontal overflow. Touch targets ≥40px.
- Add accessible labels/aria for buttons and list rows; keyboard focus visible.

- Use CSS custom props for accent colors (cyan `#5fe8ff`, amber `#ffb44a`, red `#ff5b52`). Background must remain transparent — the 3D canvas is behind. Only use localized glass fills (rgba(8,14,22,.65)) and line strokes.
